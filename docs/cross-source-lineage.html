Cross-Source Lineage

The core power of WhyValue is end-to-end provenance: tracking data from its origin (HTTP API, CSV, JSON, or Python data structure) all the way through standard pandas DataFrame transformations to final values.

End-to-End Lineage Flow

HTTP / CSV / JSON / Python  →  Tracked Container  →  why.to_dataframe()  →  pandas ops  →  why.explain()

The why.to_dataframe() API

why.to_dataframe(data) converts a TrackedList or TrackedDict into a pandas DataFrame while preserving lineage linkage across data source boundaries.

to_dataframe Signature 
def to_dataframe(data: Union[TrackedList, TrackedDict]) -> pd.DataFrame:
    """
    Converts a tracked container into a pandas DataFrame.
    Must be called inside an active why.watch() context.
    
    Attaches '_whyvalue_id' and '_whyvalue_source' metadata to df.attrs
    and registers a 'to_dataframe' provenance event.
    """

Key behavioral requirements of why.to_dataframe():

  • Must run inside watch context: Calling why.to_dataframe() outside an active why.watch() raises a RuntimeError.
  • Requires tracked input: Passing untracked objects (e.g. raw Python lists, dicts, integers, or generators) raises a TypeError.
  • Metadata propagation: Copies source metadata (file paths, HTTP endpoints, JSON paths, CSV row numbers) into df.attrs.

HTTP → Pandas Lineage (Flagship Example)

Fetch data from an external REST API, convert it to a DataFrame using why.to_dataframe(), compute derived metrics in pandas, and explain the final cell value back to the HTTP request:

http_to_pandas.py 
import pandas as pd
import whyvalue as why

with why.watch():
    # 1. Fetch JSON from HTTP API (returns TrackedList / TrackedDict)
    orders = why.get("https://api.store.com/v1/orders?status=completed&token=secret123")

    # 2. Convert tracked JSON container into a pandas DataFrame
    df = why.to_dataframe(orders)

    # 3. Perform pandas arithmetic
    df["total"] = df["subtotal"] + df["tax"]

    # 4. Explain why row 0 total is 108.0
    why.explain(df, row=0, column="total")

CSV → Pandas Lineage

Load CSV rows with why.load_csv() and convert to a DataFrame:

csv_to_pandas.py 
with why.watch():
    data = why.load_csv("sales.csv")
    df = why.to_dataframe(data)
    df["revenue"] = df["units"] * df["price"]

    why.explain(df, row=0, column="revenue")

Notice that CSV origin coordinates use 1-based data-row indexing (e.g. Row 1 = first data row below header) which maps seamlessly to DataFrame 0-indexed positions (row index 0).

JSON File → Pandas Lineage

Load nested JSON files with why.load_json() and trace field origins via JSON path notation (e.g. $.users[0].name or $["items"][0]):

json_to_pandas.py 
with why.watch():
    records = why.load_json("metrics.json")
    df = why.to_dataframe(records)
    df["score_pct"] = df["score"] * 100

    why.explain(df, row=0, column="score_pct")

Python Objects → Pandas Lineage

Wrap native Python lists or dictionaries using why.track():

python_to_pandas.py 
raw = ["10", "20", "30"]

with why.watch():
    tracked = why.track(raw)
    df = why.to_dataframe([{"val": x} for x in tracked])
    df["num"] = df["val"].astype(int) * 2

    why.explain(df, row=0, column="num")

Source-Specific Metadata Comparison

Source Type Loader API Location / Identifier Key / Position Format Special Features
HTTP API why.get() Sanitized URL JSON path ($[0].field) Masks sensitive URL query parameters (e.g. token=REDACTED), records status code & headers.
CSV File why.load_csv() File path 1-based row, column name Tracks file creation time, row index, and header names.
JSON File why.load_json() File path JSON path ($.path.key) Handles nested dicts and lists.
TXT File why.load_txt() File path 1-based line number Line-by-line provenance tracking.
Python Objects why.track() Memory reference List index / Dict key Tracks mutations in standard Python data structures.

Explanation Modes (mode="full" | "short" | "json")

When inspecting cross-source lineage, select the output format that best fits your workflow:

Explanation Modes 
# Full human-readable trace (default)
why.explain(df, row=0, column="total", mode="full")

# Concise one-line origin summary
why.explain(df, row=0, column="total", mode="short")

# Machine-readable JSON dictionary for audit logging / CI
data_dict = why.explain(df, row=0, column="total", mode="json")

Boundaries & Limitations

To maintain accurate lineage, keep these operational boundaries in mind:

  • Direct pandas readers bypass WhyValue: Standard pd.read_csv() or pd.read_json() do not pass through WhyValue adapters. Use why.load_csv() + why.to_dataframe() to capture source origin metadata.
  • Unmonitored pandas functions: Pandas operations executed outside an active why.watch() block will produce unmonitored DataFrames without provenance events.
  • Data type requirements: why.to_dataframe() requires a TrackedList or TrackedDict. Untracked lists or dicts must first be wrapped with why.track() or loaded via WhyValue loader functions.
