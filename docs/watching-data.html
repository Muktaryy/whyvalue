Watching Data

WhyValue records provenance event history only when a watch session is active.

Important: WhyValue cannot explain transformations that occurred before a watch session was started.

Supported Session Styles

1. Context Manager (Recommended)

The recommended approach is using Python's with context manager syntax:

Context Manager Syntax 
import whyvalue as why

with why.watch():
    data = why.track({"status": "pending"})
    data["status"] = "approved"
    why.explain(data, key="status")

Why it is recommended: Exiting the with block automatically cleans up and stops tracking, even if an unhandled exception occurs inside the block.

2. Manual Session

You can also manually start and stop watch sessions:

Manual Session Syntax 
import whyvalue as why

why.watch()

# Operations performed while active...

why.stop()

Checking Watch State

Use why.is_watching() to query whether a watch session is currently active:

Check Active Status 
import whyvalue as why

print(why.is_watching())  # False

with why.watch():
    print(why.is_watching())  # True

print(why.is_watching())  # False

What Happens When Watching Starts?

  • The global provenance history buffer is reset for new outer sessions.
  • Pandas adapter hooks and monkey patches are enabled.
  • Data loading wrappers (JSON, CSV, TXT, HTTP) begin attaching source metadata.

What Happens When Watching Stops?

  • Pandas adapter patches are restored to original method signatures.
  • The active watching flag is turned off.

Nested Watch Sessions

If why.watch() is called while a session is already active, WhyValue increments an internal depth counter and prints "WhyValue is already watching.". Exiting a nested context manager or calling why.stop(force=False) decrements the depth counter without stopping tracking until the outermost session exits. Calling why.stop(force=True) or why.stop() immediately terminates tracking regardless of depth.

Callout: WhyValue only explains transformations it actually observed while watching was active.
